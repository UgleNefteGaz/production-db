# Production DB

Учебный проект реляционной базы данных для учёта и контроля производственных процессов предприятия.

## Назначение проекта

База данных предназначена для моделирования производственного процесса предприятия и позволяет учитывать:

- выпускаемую продукцию;
- сырьё и материалы;
- технологические спецификации;
- производственные заказы;
- производственные партии;
- технологические операции;
- производственные линии;
- сотрудников и производственные смены;
- фактический расход материалов;
- контроль качества;
- производственный брак.

## СУБД

PostgreSQL 18.

Разработка и тестирование выполняются на PostgreSQL 18.6 в отдельном Docker-контейнере.

## Соглашение об именовании

Для таблиц, полей, индексов, ограничений, функций и триггеров используется:

```text
lowercase snake_case
```

Примеры:

```text
production_orders
production_batches
planned_quantity
production_order_id
quality_checks
```

Такой формат позволяет обращаться к объектам PostgreSQL без обязательного использования двойных кавычек.

## Триггеры

В базе реализовано 6 пользовательских триггеров.

Они контролируют:

- суммарное плановое количество партий относительно производственного заказа;
- запрет уменьшения количества заказа ниже суммы его партий;
- запрет дефектов для проверки качества с результатом `Passed`;
- запрет установки `Passed`, если у проверки уже существуют дефекты;
- соответствие времени проверки качества периоду выполнения партии;
- запрет изменения периода партии таким образом, чтобы существующие проверки качества оказались вне него.

Подробное описание находится в:

```text
docs/triggers.md
```

## Примеры SQL-запросов

Файл `sql/queries.sql` содержит практические примеры работы с PostgreSQL.

Реализованы:

- поиск с использованием регулярного выражения;
- сравнение `INNER JOIN` и `LEFT JOIN`;
- `INSERT ... RETURNING`;
- `UPDATE ... FROM`;
- `DELETE ... USING`;
- экспорт данных с помощью `COPY`.

Для изменяющих примеров `INSERT`, `UPDATE` и `DELETE` используются транзакции с `ROLLBACK`, чтобы после демонстрации основные тестовые данные сохранялись.

При использовании `INSERT ... RETURNING` следует учитывать, что `ROLLBACK` удаляет вставленную строку, но значение identity-последовательности назад не возвращается.

При использовании серверного `COPY TO` существующий файл автоматически не перезаписывается. Перед повторным экспортом файл необходимо удалить.
