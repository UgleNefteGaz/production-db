# Требования к базе данных

## 1. Предметная область

Проектируемая база данных предназначена для учёта и контроля производственных процессов предприятия.

Система должна хранить информацию о продукции, материалах, технологических спецификациях, производственных заказах, партиях, операциях, сотрудниках, производственных линиях, расходе материалов и результатах контроля качества.

## 2. Основные задачи системы

База данных должна обеспечивать:

- хранение справочника выпускаемой продукции;
- хранение справочника сырья и материалов;
- хранение технологических спецификаций продукции;
- учёт состава продукции по материалам;
- регистрацию производственных заказов;
- разделение производственных заказов на партии;
- учёт технологических операций;
- учёт выполнения операций над производственными партиями;
- учёт производственных линий;
- учёт сотрудников и производственных смен;
- учёт фактического расхода материалов;
- проведение контроля качества;
- регистрацию производственного брака;
- классификацию видов брака.

## 4. Основные бизнес-процессы

### 4.1. Создание производственного заказа

Для выпуска продукции создаётся производственный заказ, содержащий используемую технологическую спецификацию, плановое количество продукции и сроки производства.

### 4.2. Формирование производственных партий

Один производственный заказ может быть разделён на несколько производственных партий.

### 4.3. Выполнение технологических операций

Для каждой производственной партии фиксируются выполняемые технологические операции, производственная линия, сотрудник, смена, время выполнения и количество обработанной продукции.

### 4.4. Расход материалов

Для производственной партии регистрируется фактический расход сырья и материалов.

Нормативный расход определяется на основании технологической спецификации продукта.

### 4.5. Контроль качества

Для производственных партий проводятся промежуточные и итоговые проверки качества.

По результатам проверки фиксируется результат контроля и обнаруженные дефекты.

### 4.6. Учёт брака

Каждый обнаруженный дефект относится к определённому типу брака и содержит количество дефектной продукции.

## 5. Требования к целостности данных

В базе данных должны использоваться:

- первичные ключи;
- внешние ключи;
- ограничения NOT NULL;
- ограничения UNIQUE;
- проверки допустимых значений;
- контроль ссылочной целостности.

## 6. СУБД

В качестве системы управления базами данных используется PostgreSQL.
